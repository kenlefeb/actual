# Release 26.10.1-alpha.19 — Ken’s Actual fork

October 30, 2026

**Unofficial fork prerelease.** Based on upstream Actual `master` at `21c2b3f703142f858af4c653a31e675ca5ff85d7` (October 26, 2026), which comes after Actual 26.10.0 and is not itself an upstream release; not an official Actual Budget release.

This release lets you move an off-budget account on budget, keeps paycheck schedules consistent after edits on several devices, shows skipped dates in paycheck and schedule editors, and makes secondary and warning text easier to read in every theme. Paycheck and business calendar screens work better on a phone.

Docker Tag: `ghcr.io/kenlefeb/actual-hosting:run-<successful workflow run>-1` (private; see the accompanying `image.ref`, `image.id` and `source.json` for exact provenance).

#### Features

- Move an off-budget account on budget from its account menu, on desktop and on a phone. You pick the start date, see the starting balance first, and can undo the move. An invalid start date is refused.

#### Enhancements

- Transactions from before an account moved on budget show as moved history instead of uncategorized, and Actual asks before you categorize them.
- Secondary and warning text is easier to read in every theme.
- The clearing-account note and the paycheck schedule note are easier to read in every theme.
- On a phone, the paycheck editor stacks the deduction and deposit fields, each with a short visible label.
- On a phone, deleting a paycheck or a business calendar uses the same delete sheet as the rest of the app.
- Deleting a business calendar names the calendar and says what deleting it changes.

#### Bugfixes

- Paycheck schedules are reconciled after edits made on several devices at once, so they no longer drift apart.
- "Upcoming dates" in schedule and paycheck editors start from the schedule's next date, so skipped dates show.
- A goal template for a schedule dated relative to another schedule keeps working after the schedule it follows is deleted.
- Deleting a paycheck on a phone returns to Schedules.

#### Maintenance

- Pages that show schedule dates share one schedules query instead of each running its own.
- The web worker no longer bundles an unused cryptography library.
- A development-only dependency advisory (`qs`) is resolved.
- Fork checks now run on every merged commit on `development`, so the combined result is tested, not only each pull request.
- A nightly report runs mutation tests on the shared date and money code and lists spec scenarios that no test names.
- Phone page-heading tests catch text that is clipped sideways as well as vertically.
- A test fixture uses placeholder names.

#### Known limitations

- Experimental.
- Upstream changes made after 26.10.0 have not yet been through an upstream release.
- Each deposit must go to a different account, and every paycheck repeats its defined amounts; edit a posted transaction for a one-off change.
- Imported deposits more than about 7.5% from the expected amount do not link automatically.
- A duplicate of the latest paycheck (for example, imported twice) can hide the next skipped date.
- Goal templates already applied under alpha.17 keep their amounts until templates are applied again.
- Each device's own sign-in limit (from alpha.18) takes effect only after the server's proxy setting is updated; until then, one device's failed sign-ins can still lock out others.
- Releases published on the same day may show the "What's new" message for any of them; the Notifications page lists all.
- No iPhone acceptance test is claimed.
