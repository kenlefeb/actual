# Release 26.10.1-alpha.20 — Ken’s Actual fork

October 31, 2026

**Unofficial fork prerelease.** Based on upstream Actual `master` at `21c2b3f703142f858af4c653a31e675ca5ff85d7` (October 26, 2026), which comes after Actual 26.10.0 and is not itself an upstream release; not an official Actual Budget release.

This release fixes the year-to-date rows on the phone paycheck page, keeps Save in view on the phone edit pages, asks only once before moved history is categorized, and explains goal template errors for schedules whose source was deleted.

Docker Tag: `ghcr.io/kenlefeb/actual-hosting:run-<successful workflow run>-1` (private; see the accompanying `image.ref`, `image.id` and `source.json` for exact provenance).

#### Features

- None in this release.

#### Enhancements

- On a phone, the paycheck, business calendar, schedule, transaction, payee, bank sync and rule edit pages keep Save in view at the bottom of the screen. On the bank sync and rule pages, Unlink and Delete move to the end of the form.
- Applying a rule from the Rules page asks once before it would categorize transactions from before an account moved on budget.
- A goal template error for a schedule dated relative to another schedule now says that source schedule was deleted, instead of wrongly saying the schedule is in the past.

#### Bugfixes

- On the phone paycheck page, the year-to-date rows no longer overlap the Skip and Delete buttons.
- On the phone rule edit page, the last action row is no longer cut off behind the Save button.
- Categorizing a moved-history transaction in the transaction table opens one confirmation instead of two.

#### Maintenance

- The sync server's query-string library is pinned to a version that clears three security advisories.
- Business-day checks for schedules reuse each calendar's holidays per year instead of rebuilding them every time.
- Shared schedule date code no longer pulls server rule code into the client.
- Phone screenshot tests run in fork CI with fresh baselines, and several end-to-end tests no longer depend on the date or on timing.
- Agent workflow documentation updates.

#### Known limitations

- Experimental.
- Upstream changes made after 26.10.0 have not yet been through an upstream release.
- Each deposit must go to a different account, and every paycheck repeats its defined amounts; edit a posted transaction for a one-off change.
- Imported deposits more than about 7.5% from the expected amount do not link automatically.
- A duplicate of the latest paycheck (for example, imported twice) can hide the next skipped date.
- Goal templates already applied under alpha.17 keep their amounts until templates are applied again.
- Releases published on the same day may show the "What's new" message for any of them; the Notifications page lists all.
- No iPhone acceptance test is claimed.
