# Release 26.10.1-alpha.22 — Ken’s Actual fork

November 2, 2026

**Unofficial fork prerelease.** Based on upstream Actual `master` at `21c2b3f703142f858af4c653a31e675ca5ff85d7` (October 26, 2026), which comes after Actual 26.10.0 and is not itself an upstream release; not an official Actual Budget release.

This release adds a hosted, read-only entry for the MCP server, a content-free access log for the sync server, and a clearer record of who acted through the MCP server.

Docker Tag: `ghcr.io/kenlefeb/actual-hosting:run-<successful workflow run>-1` (private; see the accompanying `image.ref`, `image.id` and `source.json` for exact provenance).

#### Features

- The MCP server has a hosted, read-only entry that serves the Model Context Protocol over streamable HTTP, with sync freshness checks and rate limits. It includes an OAuth provider and token store, so only the one configured account can sign in through the identity provider. It serves staging only, refuses a production host even with the override, and is not deployed by this release.

#### Enhancements

- Every MCP audit line records the sync-server user id and the OAuth subject (`local` on stdio).
- The MCP server can sign in with a session token read from a file that only its owner can read (mode 0400).
- The sync server writes a content-free access log (no budget content, no passwords) and ships a runbook for keeping it off the host.
- The sync server logs access decisions on every file route, and new uploads.
- The hosted MCP entry carries the verified OAuth subject on its access lines, requires a long client secret, and refuses loopback redirects.

#### Bugfixes

- None in this release.

#### Maintenance

- Documentation for the hosted MCP identity provider (Auth0 as the example) and what any provider must support.
- OpenSpec records for the production-identities design and the OpenID staging rehearsal findings.
- The `actual-mcp-http` command is recorded in `yarn.lock`.

#### Known limitations

- Experimental.
- Upstream changes made after 26.10.0 have not yet been through an upstream release.
- The hosted MCP entry is not deployed anywhere yet. It serves staging only and refuses a production host even with the override. It is read-only; production is unchanged.
- The stdio MCP server still runs on your own computer and needs Node.js 22 or later and the 1Password CLI.
- No iPhone acceptance test is claimed.
