# Release 26.10.1-alpha.23 — Ken’s Actual fork

November 3, 2026

**Unofficial fork prerelease.** Based on upstream Actual `master` at `21c2b3f703142f858af4c653a31e675ca5ff85d7` (October 26, 2026), which comes after Actual 26.10.0 and is not itself an upstream release; not an official Actual Budget release.

This release lets a server owner require that the first OpenID sign-in is a named person, refuses an empty OpenID identity, and tightens the rate limits and start-up checks of the hosted MCP entry. The hosted MCP entry is still not deployed anywhere.

Docker Tag: `ghcr.io/kenlefeb/actual-hosting:run-<successful workflow run>-1` (private; see the accompanying `image.ref`, `image.id` and `source.json` for exact provenance).

#### Features

- A new, optional setting, `ACTUAL_OPENID_ADMIN_SUBJECT`, names the provider subject (`sub`) that the first OpenID sign-in must have. When it is set, a first sign-in from any other identity is refused, so the first person to reach the sign-in page cannot become the administrator. Unset, the server behaves as upstream does: the first OpenID identity becomes the administrator, and the server logs a warning at start-up.
- The hosted MCP entry can serve a production host, read-only, but only when `ACTUAL_MCP_REMOTE_PRODUCTION=1` is set and the production guard is met: a session token file and no password, a provider subject (not an email address) as the allowed account, the data folder `production-remote`, and a token that belongs to a user who is not an administrator. Otherwise it still refuses a production host. It is not deployed anywhere yet.

#### Enhancements

- The hosted MCP entry limits its OAuth endpoints per source address and adds a ceiling over each /24 (IPv4) or /48 (IPv6) group of sources, set with `ACTUAL_MCP_RATE_PER_PREFIX` (default 600 per window). A request to `/mcp` with a valid token counts only against the per-client limit.
- The hosted MCP entry refuses to start with a loopback server address unless it also listens on loopback.
- The MCP image build leaves local `.env` files (`.env`, `.env.local` and `.env.*.local`) out of its build context.

#### Bugfixes

- The sync server now refuses an OpenID sign-in whose identity is empty. Upstream would have matched an empty identity to the password-method user. This fixes a flaw in upstream's code; it is fixed here only.
- When `ACTUAL_OPENID_ADMIN_SUBJECT` is set, the sync server also refuses a sign-in whose ID-token `sub` differs from the user-info `sub`.

#### Maintenance

- OpenSpec records for the production identities (the production sync server uses an Auth0 tenant) and for the hosted MCP entry serving production under an explicit guard.
- The MCP README documents the new settings.

#### Known limitations

- Experimental.
- Upstream changes made after 26.10.0 have not yet been through an upstream release.
- The hosted MCP entry is not deployed anywhere yet. It is read-only, and it still refuses a production host unless the production guard above is met.
- `ACTUAL_OPENID_ADMIN_SUBJECT` only affects the first sign-in; it does not change an administrator that already exists.
- The stdio MCP server still runs on your own computer and needs Node.js 22 or later and the 1Password CLI.
- No iPhone acceptance test is claimed.
