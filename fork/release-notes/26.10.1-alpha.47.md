# Release 26.10.1-alpha.47 — Ken’s Actual fork

November 20, 2026

**Unofficial fork prerelease.** Based on upstream Actual v26.11.0 (`1766241e3f4b3c578e424c4fa15f1eb83c0da17d`, October 29, 2026); not an official Actual Budget release.

This release fixes the MCP server refusing every write, and adds MCP undo of moves. Most other changes are for the iPhone app and reach Ken only with a new TestFlight build.

**What Ken will notice on first load.** Nothing visible in the web app or on the sync server: the storage guard is off in browsers, there are no new budget migrations, and nothing needs configuring. Through the MCP, writes work again, and closing or deleting a bank-linked account and applying budget templates now always ask for a confirmation call first, while other deletes still follow the `confirm_destructive` setting, which production has on. The iPhone changes below arrive only in the next TestFlight build, which is held for the crash in sc-5504.

Docker Tag: `ghcr.io/kenlefeb/actual-hosting:run-<successful workflow run>-1` (private; see the accompanying `image.ref`, `image.id` and `source.json` for exact provenance).

#### Features

- MCP: undo for category and category group moves (#440, #454), and every write now declares whether it can be undone, with its undo record checked up front; closing or deleting a bank-linked account and applying budget templates always need a confirmation call first (other deletes still follow `confirm_destructive`) (#449).
- iPhone: a native Add transaction form with payee search and a preview, saved as one undo step (#447, #451; design notes #442, #444, #450, #453, #457).
- iPhone: native Settings, with one validated save and a limits registry (#448, #446).
- iPhone: upcoming scheduled rows in the account register, shown as they will post, with search that finds a row by a payee name no payee has yet, and scheduled splits that show the payee the web shows (#445, #452, #456, #462, #465, #471, #472, #475).
- iPhone: the native Budget and Schedules & Paychecks screens (#438, #455) and the native Accounts screens (#459, #461) are on by default; each has a switch in Settings to go back to the web screen.

#### Enhancements

- iPhone: Accounts amounts stay whole and search is always visible (#476); VoiceOver fixes on Accounts (#479); the Undo button sits under its text at accessibility sizes (#504); the account menu no longer reopens after a reload (#458, #460).
- iPhone: the app reloads its own page when its web process ends and tells the person (#484, #489).
- iPhone: the storage status line and notices are placed clear of the keyboard, menus, sheets and the bottom search field (#488, #494, #495, #501, #486).
- Mac app shell: it reloads its page when the web process ends, a reload closes a page dialog, Safari's Web Inspector can attach to Debug builds, and the shells show page alerts, confirms and prompts (#466, #506, #463, #500).

#### Bugfixes

- The MCP server refused every write with "The loaded budget has no id" since the undo and audit change shipped, while reads kept working. Writes work again (#508).
- A budget database migration and its "applied" record are now saved as one transaction, so a crash or kill between them can no longer leave a budget that never opens again (#502). This runs in every client that opens a budget (web, desktop, iPhone, and the API and MCP); the sync server does not run budget migrations. A budget that was already stuck with the 2023 account-type migration applied but not recorded is recorded instead of run again; no other half-applied migration is repaired. One migration, the old cache removal, no longer compacts the database. This build adds no new migrations, so nothing changes on first load for a budget that is already up to date.

#### Maintenance

- iPhone durable writes (the storage guard), with the `native/*` handlers in loot-core gated so they do nothing without a native shell: a storage engine that waits for IndexedDB and sends only stored changes, a page bridge that checks storage, a storage barrier after every native write, storage status and the held-sync line, a flush before the app goes to the background, "Saved" shown only once a write is stored, notices, and a per-shell switch (#473, #481, #482, #483, #485, #487, #490, #491, #492, #493, #496). The guard stays off in browsers. #505 turns it on in the iPhone app source, and #507 makes native reads wait for the budget to open; both reach Ken only with a new TestFlight build.
- Tests and CI: iPhone kill tests with 50 delayed kills, an iPhone UI-test target on the simulator, a release archive check that scans only compiled code, and test fixes (#464, #477, #480, #498, #499, #503).
- Specs and records: failure-notice copy, native writes that reply once stored, storage status wording, the Reconcile alert and the Mac release-flags check (#467, #468, #469, #474, #478, #497).
- No upstream changes in this release; the fork stays on upstream Actual 26.11.0.

#### Known limitations

- Removing a deduction from a paycheck in the iPhone app can crash. The fix is tracked in sc-5504, and the next iPhone TestFlight build is held for it.
- Experimental.
- Tapping a tag in the transaction editor does nothing.
- Tags are not yet fully accessible on the phone.
- OpenID sign-out needs the server's address in the identity provider's allowed sign-out addresses; without it the provider shows an error page, though you are already signed out of Actual.
- Attached documents aren't included in a budget export.
- Documents removed before alpha.35 are recorded the first time an updated device syncs, and deleted 30 days after that. Removals made on a device that has not been updated are not tracked.
- HEIC pictures are refused; use the Photos library or a JPEG or PNG copy.
- Attaching a document needs a connection; there is no offline upload queue.
- After restoring server data from a backup, pause the cleanup first (`production/RESTORE.md`).
