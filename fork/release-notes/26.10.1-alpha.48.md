# Release 26.10.1-alpha.48 — Ken’s Actual fork

November 20, 2026

**Unofficial fork prerelease.** Based on upstream Actual v26.11.0 (`1766241e3f4b3c578e424c4fa15f1eb83c0da17d`, October 29, 2026); not an official Actual Budget release.

This release adds MCP tools to create and change schedules and to create payees, and carries a source fix for the iPhone paycheck-editor crash (not yet confirmed on a device). Nothing changes in the web app or on the sync server, and no iPhone app is built from it.

Docker Tag: `ghcr.io/kenlefeb/actual-hosting:run-<successful workflow run>-1` (private; see the accompanying `image.ref`, `image.id` and `source.json` for exact provenance).

#### Features

- MCP: schedule tools (#512). `write_create_schedule` creates a schedule as the app's form does (payee and account by id, an exact, approximate or ranged amount, and one date form: a day, a recurrence or relative to another schedule). `write_update_schedule` changes the fields you give and shows each field before and after; it refuses a schedule that a paycheck manages. `write_skip_schedule_date` skips a schedule's next date, as the app's "Skip next date" does. `write_post_schedule_transaction` posts a schedule's transaction, as "Post transaction" does, or today's with `today`. Create and update accept `dry_run`, which shows the next dates and writes nothing. The API package also gains two wrapper methods for these, `skipScheduleNextDate` and `postScheduleTransaction`.
- MCP: `write_create_payee` creates a payee by name (#514). A name that matches a live payee ignoring case returns that payee with `created` false and writes nothing; a transfer payee's name is refused.
- What each needs from Ken's grant: `schedules:write` for create, update and skip; both `schedules:write` and `transactions:write` for post; `structure:write` for create payee.
- Undo: create schedule and update schedule can be undone with `write_undo`, and so can create payee while the payee is unused. Skip and post cannot: put back a skipped date by hand, and delete the transaction a post added with `write_delete_transactions`. An update's `reset_next_date` is also not undone by `write_undo`.

#### Enhancements

- MCP: `list_schedules` now returns what an edit needs: payee and account ids, the amount operator and amount (or the minimum and maximum of a range), the date definition, whether it posts a transaction, and the id of the paycheck that manages the schedule, if any (#512).

#### Bugfixes

- iPhone app: removing a deduction from a paycheck should no longer crash (#510, sc-5504). The paycheck editor now reads and writes deduction and deposit rows by id; the pay-day rows are still by position, behind a bounds check. This is fixed in source and not yet confirmed on a device (sc-5504 stays open for that check). The iPhone build is held, so it reaches Ken's iPhone only when someone starts an iPhone build by hand.

#### Maintenance

- iOS build held: this release does not build or upload an iPhone app to TestFlight. The hold switch is `buildOnRelease` in `ios-release.json` in the hosting repository (default off); start the `ios.yml` workflow by hand to build one.
- Specs: proposals for the MCP schedule writes with paycheck create and delete, and for `write_create_payee` (#511, #513).
- No upstream changes in this release; the fork stays on upstream Actual 26.11.0.

#### Known limitations

- Removing a deduction from a paycheck in the iPhone app can crash in any iPhone build made before alpha.48. The fix (#510) is in this release's source but not yet confirmed on a device, but no iPhone build is made from it until someone starts one (see Maintenance).
- Experimental.
- Tapping a tag in the transaction editor does nothing.
- Tags are not yet fully accessible on the phone.
- OpenID sign-out needs the server's address in the identity provider's allowed sign-out addresses; without it the provider shows an error page, though you are already signed out of Actual.
- Attached documents aren't included in a budget export.
- Documents removed before alpha.35 are recorded the first time an updated device syncs, and deleted 30 days after that. Removals made on a device that has not been updated are not tracked.
- HEIC pictures are refused; use the Photos library or a JPEG or PNG copy.
- Attaching a document needs a connection; there is no offline upload queue.
- After restoring server data from a backup, pause the cleanup first (`production/RESTORE.md`).
