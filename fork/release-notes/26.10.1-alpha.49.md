# Release 26.10.1-alpha.49 — Ken’s Actual fork

November 21, 2026

**Unofficial fork prerelease.** Based on upstream Actual v26.11.0 (`1766241e3f4b3c578e424c4fa15f1eb83c0da17d`, October 29, 2026); not an official Actual Budget release.

This release adds MCP tools to delete schedules and to create and delete paychecks, and makes the iPhone native screens re-read when a slow budget finishes opening (the Mac engine host routes the event too). Nothing changes in the web app's look or on the sync server, and no iPhone app is built from it.

Docker Tag: `ghcr.io/kenlefeb/actual-hosting:run-<successful workflow run>-1` (private; see the accompanying `image.ref`, `image.id` and `source.json` for exact provenance).

#### Features

- MCP: `write_delete_schedule` deletes a schedule (#519). It refuses a schedule that a paycheck manages. It always takes two steps, whatever `confirm_destructive` says: a dry run that returns the schedule's definition, next date, linked transactions and relative dependents, then a call with the confirmation. It needs `schedules:write` and `delete`, and it cannot be undone; recreate the schedule from the dry run's definition (a restore is planned in sc-5522).
- MCP: `write_create_paycheck` creates a paycheck and its pay and deposit schedules as the app's form does, with an existing clearing account and deductions and deposits within the row limit (#519). It needs `schedules:write`. It can be undone with `write_undo` while no pay has posted; an undo cannot see a pay posted by hand, and deleting a paycheck never deletes posted transactions. It changes no account's business calendar or days early.
- MCP: `write_delete_paycheck` deletes a paycheck and its schedules (#519). It always takes two steps; its dry run returns the definition as `write_create_paycheck` inputs. It needs `schedules:write` and `delete`, and it cannot be undone yet (a restore is planned in sc-5522).

#### Enhancements

- iPhone native screens: when a slow open makes a native screen's first read refused, the budget now announces that it has finished opening and the Budget, Accounts and Paychecks screens read again, so they no longer stay empty (#518, spec #516). The Mac engine host routes the same event, but the Mac app has no native screens yet. This is in the source only; the iPhone app Ken uses does not have it until an iPhone build is made.

#### Bugfixes

- iPhone app: a sync's "syncing" flag is now cleared before the sync's result reaches the caller, so a second call straight after the first no longer sees the first as still running (#517, sc-5540). This is in the source only.

#### Maintenance

- iOS build held: this release does not build or upload an iPhone app to TestFlight. The hold switch is `buildOnRelease` in `ios-release.json` in the hosting repository (default off); start the `ios.yml` workflow by hand to build one.
- loot-core sends a new internal `budget-opened` event when a budget finishes opening (#518). Browsers and the API ignore it, so nothing is visible in the web app or for the MCP. Test-only hooks that slow the open down are compiled in only for test builds, and Fork CI checks that a production bundle lacks them.
- Tests and CI (#517): one iPhone page-dialog UI test now reloads the page on a Darwin notification the test sends, instead of after a timer; the iOS simulator job waits for the simulator to boot, builds once, and launches the app once before the tests so the first test starts on a warm simulator (not a retry); and one real sync-flag race, fixed in app code (see Bugfixes), has a new test. The storage-line UI tests are unchanged. New tests also cover the budget-opened signal in the iPhone bridge and the Mac engine host (#518).
- Spec: the budget-opened signal proposal (#516).
- No upstream changes in this release; the fork stays on upstream Actual 26.11.0.

#### Known limitations

- Removing a deduction from a paycheck in the iPhone app can crash in any iPhone build made before alpha.48. The fix (#510, in alpha.48) is in source but not yet confirmed on a device, and no iPhone build is made from it until someone starts one (see Maintenance).
- Experimental.
- Tapping a tag in the transaction editor does nothing.
- Tags are not yet fully accessible on the phone.
- OpenID sign-out needs the server's address in the identity provider's allowed sign-out addresses; without it the provider shows an error page, though you are already signed out of Actual.
- Attached documents aren't included in a budget export.
- Documents removed before alpha.35 are recorded the first time an updated device syncs, and deleted 30 days after that. Removals made on a device that has not been updated are not tracked.
- HEIC pictures are refused; use the Photos library or a JPEG or PNG copy.
- Attaching a document needs a connection; there is no offline upload queue.
- After restoring server data from a backup, pause the cleanup first (`production/RESTORE.md`).
