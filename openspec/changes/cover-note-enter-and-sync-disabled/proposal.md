# Proposal

## Why

Two baseline behaviors lack evidence. Plain Enter in the desktop note editor saves the note and moves to the next row, but `transaction-notes` does not specify it and no test checks the save (upstream's save-on-move test lists Enter but only ever presses Tab). The `mobile-sync-status` requirement that a sync-disabled budget reads as a local file is specified but only the no-server case is tested.

## What Changes

- Specify that plain Enter in the desktop note editor saves the note, keeping its line breaks, and moves to the same field in the next row.
- Add a desktop test proving Enter saves an edited multiline note and moves down.
- Add a mobile sync status test proving a sync-disabled budget shows "Local file — not syncing" with no sync control.
- Exclude `openspec/` and OpenSpec-generated agent files from the formatter, which currently fail `yarn lint` because they were committed unformatted and are regenerated by `openspec update`.
- No application code changes. Upstream's existing save-on-move test is left unchanged to avoid merge conflicts.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `transaction-notes`: the desktop multiline note entry requirement adds plain Enter's save-and-move-down behavior.

## Impact

- Tests: `packages/desktop-client/src/components/transactions/TransactionsTable.test.tsx`, `packages/desktop-client/src/components/mobile/MobileSyncStatus.test.tsx`.
- Specs: `openspec/specs/transaction-notes/spec.md` after archive.
- Tooling: `.oxfmtrc.json` ignore list.
- If either new test fails, it exposes a behavior bug, which would be fixed in a separate change.
